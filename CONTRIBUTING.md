# Contributing

Contributions are welcome once the repository is published.

1. Start with an issue describing the user problem and expected outcome.
2. Keep changes small and independently reviewable.
3. Add or update tests for every behavior change.
4. Run `ruff check .`, `mypy`, and `pytest` before opening a pull request.
5. Never include credentials, secret-manager paths, or private Jira metadata.

Product changes should include observable acceptance criteria and explain how success will be measured.
